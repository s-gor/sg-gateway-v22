# Сведения об IP в SG InfoSec

SG InfoSec показывает рядом с внешним IP понятные сведения о сети:

- страну по локальной базе GeoIP SG-Gateway;
- номер автономной системы, например `AS7488`;
- название оператора или организации, объявляющей сеть;
- маршрутизируемый префикс, например `144.225.6.0/23`;
- тип сети из локальной репутации: хостинг, Tor, прокси, VPN, ботнет или сканер.

## Что означает «чей адрес»

Публичные данные описывают сеть и её оператора. Они не устанавливают личность человека, который выполнил запрос. Надпись вида:

```text
🇺🇸 США · AS7488 · CNServer LLC
Сеть 144.225.6.0/23 · Сеть хостинг-провайдера
```

означает, что адрес относится к указанному маршрутизируемому префиксу и автономной системе. Это не утверждение о конкретном владельце устройства или личности нарушителя.

## Источники данных

Страна определяется локально по установленной GeoIP-базе SG-Gateway. ASN, сетевой префикс и название оператора запрашиваются у публичного API RIPEstat `prefix-overview`.

Во внешний сервис передаётся только проверяемый публичный IP-адрес. Пароли, cookies, токены, URL, содержимое запросов, данные клиентов и конфигурации не отправляются.

## Кэш и отказоустойчивость

Результат сохраняется на семь дней в:

```text
/var/lib/sg-gateway/infosec/ip-intelligence.json
```

Кэш ограничен 4096 адресами и размером 2 МБ. Запись выполняется атомарно. На одной странице выполняется не более 12 новых запросов, одновременно — не более четырёх. Тайм-аут одного запроса не превышает одной секунды.

Если RIPEstat или сеть недоступны:

- страница Security продолжает открываться;
- блокировки и Web Shield продолжают работать;
- показывается локально известная страна и пометка «Сведения о сети недоступны»;
- ошибка внешнего справочного сервиса не создаёт и не снимает решения.

## Влияние на блокировку

Сведения RIPEstat предназначены только для объяснения события администратору. ASN, название оператора и префикс из RIPEstat не повышают риск и сами по себе не создают блокировку.

На решение влияют только:

- правила SG InfoSec и Web Shield;
- локальная репутация, которую администратор явно загрузил в панель;
- ручные действия администратора;
- allowlist.

Тип сети показывается только при наличии соответствующего тега в локальной репутации:

| Тег | Отображение |
|---|---|
| `hosting` | Сеть хостинг-провайдера |
| `tor` | Узел Tor |
| `proxy` | Прокси-сеть |
| `vpn` | VPN-сеть |
| `botnet` | Ботнет |
| `scanner` | Сеть сканера |

Без такого тега интерфейс пишет «Публичная сеть» и не делает предположений по названию ASN.

## Понятные названия действий

Основной экран скрывает внутренние коды и показывает их смысл:

| Техническое значение | В интерфейсе |
|---|---|
| `ssh` | Вход на сервер (SSH, порт 22) |
| `admin-login` | Вход в панель |
| `admin-api` | API панели |
| `threshold_exceeded` | Превышен лимит неудачных попыток |
| `active` | Активна |
| `decision.auto_created` | Автоматически создана блокировка |
| `success` | Успешно |
| `sensitive-path` | Сканирование закрытых путей |
| `path-traversal` | Попытка выхода за каталог |
| `sqli` | SQL-инъекция |
| `xss` | XSS |
| `command-injection` | Командная инъекция |

Исходные идентификаторы, backend, policy ID и точные временные метки остаются доступными в раскрывающемся блоке «Технические данные».

## Отключение внешнего справочного запроса

Для полного запрета обращений к RIPEstat добавьте в systemd override панели:

```ini
[Service]
Environment=SG_INFOSEC_IP_INTEL_ENABLED=0
```

Затем выполните:

```bash
sudo systemctl daemon-reload
sudo systemctl restart sg-gateway.service
```

После отключения локальная GeoIP-страна и локальная репутация продолжают отображаться. ASN, оператор и сетевой префикс обновляться не будут.

Справочная функция не меняет nftables, SSH, AWG, маршрутизацию, подписки и VPN-порты 585–587.
