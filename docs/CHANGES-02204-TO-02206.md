# SG-Gateway: отличия 0.1.0-022.06 от 0.1.0-022.04

Этот документ перечисляет пользовательски значимые изменения между стабильными выпусками. Внутренние CI-коммиты, временные repair-workflow и технические перестановки файлов не считаются отдельными возможностями.

## Кратко

**022.04** заложила Dual Stack, AWG 3.0 userspace, семейную маршрутизацию, WARP по семействам, базовую SG Subscription и безопасный updater.

**022.06** добавляет третье независимое поколение AWG, расширяет работу с клиентами и роутерами, усиливает переносимость Backup/Restore, формализует Clean Install/Update/Full Uninstall и закрывает большое число эксплуатационных дефектов.

## Что нового в 022.06

### 1. Три независимых поколения AmneziaWG

В 022.06 одновременно доступны:

- AWG 2.0 — UDP 585;
- AWG 3.0 userspace — UDP 586;
- AWG 3.1 userspace — UDP 587.

Каждый профиль имеет собственный runtime, интерфейс, службу, серверное состояние, ключи, peers, credentials и клиентский экспорт. AWG 3.1 не заменяет AWG 2.0 или AWG 3.0.

### 2. Полная интеграция AWG 3.1

Добавлены:

- отдельный userspace runtime 3.1;
- systemd-служба и интерфейс `awg31`;
- HeaderProtectionKey и расширенные параметры протокола;
- безопасные диапазоны H1–H4;
- создание, применение и удаление peers;
- `.conf`, URI и QR;
- выбор AWG 3.1 при создании клиента и устройства;
- включение в подписки;
- Backup/Restore;
- восстановление runtime;
- атомарное добавление AWG 3.1 при Update.

### 3. Единый DNS для AWG 2.0, 3.0 и 3.1

DNS задаётся одной настройкой. Изменение синхронизирует три профиля и существующие credentials без смены клиентских ключей. Поддерживается от одного до четырёх IPv4- или IPv6-адресов.

### 4. Усилен жизненный цикл AWG 3.0

Исправлены и проверены:

- чистая установка runtime;
- сохранение unit-файла при Update;
- первый клиент AWG 3.0;
- состояние неиспользуемого профиля;
- восстановление runtime;
- сохранение ключей и конфигурации;
- полный uninstall интерфейса, socket и службы;
- повторная установка на том же сервере.

### 5. Полный профильный набор для первоначального администратора

`sg-admin` получает базовый комплект для проверки установки:

- VLESS Reality TCP;
- VLESS XHTTP Reality;
- AWG 2.0;
- AWG 3.0;
- AWG 3.1;
- Mieru;
- служебный SG Client access.

### 6. Атомарное создание клиентов

Создание и изменение доступа переведено на более строгий контракт:

- неполные AWG credentials не выдаются как рабочие;
- отключённый Xray-профиль не экспортируется;
- проверяется полнота обязательных полей;
- ошибка одного выбранного протокола откатывает незавершённые изменения;
- устаревшие записи не должны продолжать выглядеть активными.

### 7. AWG-only клиенты и устройства

Можно создать доступ только с AWG 2.0, 3.0 и/или 3.1 без обязательного SG Client или Xray. Для такого доступа используются отдельные файлы и QR; обычная SG Subscription может отсутствовать.

### 8. Унифицированный выбор протоколов

Диалоги клиентов и устройств приведены к одной логике:

- отдельные AWG 2.0, 3.0 и 3.1;
- одинаковый порядок протоколов;
- корректное редактирование существующего выбора;
- сохранение AWG-only сценария;
- учёт готовности HTTPS для TLS-протоколов.

### 9. Строгая изоляция устройств

Каждое устройство имеет собственные:

- UUID и пароли;
- AWG-ключи;
- credentials;
- подписки;
- QR-коды;
- файлы экспорта.

### 10. Расширенная SG Subscription

Доработано:

- отдельные профили AWG 3.0 и AWG 3.1;
- корректные имена дополнительных устройств;
- отсутствие искусственного имени у основного устройства;
- AWG-only подсказки;
- перенос subscription token;
- представление QR;
- совместимость Base64 и текстового формата.

### 11. Router JSON Subscription

Добавлена отдельная подписка для роутеров и совместимых интеграций. В том числе реализованы варианты, рассчитанные на OpenWrt/HomeProxy и Keenetic/XKeen.

Router JSON Subscription не является обычной SG Subscription и создаётся отдельно для конкретного устройства.

### 12. Экспорты, QR и загрузка ключей

Добавлены и исправлены:

- отдельные AWG-файлы по поколениям;
- AWG 3.1 URI;
- QR профилей и подписок;
- понятные подписи типов QR;
- корректные имена файлов и устройств;
- загрузка клиентского набора;
- запрет пустых или неполных экспортов.

### 13. Переносимые Clients & Keys

Клиенты, устройства, UUID, пароли, AWG credentials, выбранные протоколы и subscription token могут переноситься без жёсткой привязки к IP старого сервера. Публичные endpoint формируются из текущего состояния восстановленной установки.

### 14. Расширенный Full Backup

В резервную копию добавлены и усилены:

- AWG 3.1;
- состояние трёх AWG-профилей;
- клиентские credentials;
- подтверждённое HTTPS-состояние;
- сертификаты;
- runtime metadata;
- server-independent Clients & Keys;
- проверка структуры и SQLite;
- загрузка больших backup без прежнего ограничения размера.

### 15. Усиленный Full Restore

Restore теперь строже проверяет архив и состояние после применения:

- проверка до замены данных;
- Safety Backup текущего сервера;
- безопасная миграция базы;
- пересборка runtime вместо слепого копирования;
- проверка обязательных служб;
- проверка HTTPS и Nginx;
- safety rollback при критической ошибке;
- фоновый журнал этапов.

### 16. SQLite Restore и DATA Backup

Добавлена загрузка отдельного SQLite-файла с предварительной проверкой и страховочной копией. Появился отдельный DATA Backup для переносимых данных и runtime-контрактов, когда полный системный архив не требуется.

### 17. Более строгий Update

В 022.06 updater дополнительно поддерживает:

- закрепление exact commit SHA;
- source integrity;
- staging до переключения;
- сохранение unit-файлов и состояния служб;
- AWG 3.0 и AWG 3.1 в общей транзакции;
- восстановление кода, базы, конфигураций и runtime при ошибке;
- безопасное чтение env-файлов как данных, а не shell-кода;
- проверки Panel, HostD, HTTPS и VPN runtime после обновления.

### 18. Строгий Clean Install

Clean Install отделён от Update и выполняет:

- проверку Ubuntu 24.04;
- ожидание `cloud-init`;
- проверку диска;
- обновление Ubuntu;
- обработку обязательной перезагрузки;
- установку AWG 3.0 и 3.1 runtime;
- проверку приложения, базы и основных страниц;
- блокировку запуска поверх существующей установки.

### 19. Официальный Full Uninstall

Опубликована стабильная команда полного удаления. Она очищает приложение, данные, SG-службы, управляемые конфигурации, интерфейсы и runtime, но не удаляет общие пакеты Ubuntu.

Для подтверждения требуется строка `DELETE SG-GATEWAY`.

### 20. Проверенный цикл удаления и повторной установки

Отдельно проверен сценарий:

1. Clean Install;
2. Full Uninstall;
3. проверка очистки;
4. повторный Clean Install;
5. запуск панели, AWG 3.0 и AWG 3.1.

### 21. Публичный стабильный канал GitHub

Команды Clean Install, Update и Full Uninstall используют ветку `stable-02206`. Пользователю не требуется временная feature-ветка или SHA разработчика.

### 22. Совместный перезапуск Mihomo и sing-box

Операция перезапуска обрабатывает применённые конфигурации двух движков:

- `mihomo.service`;
- `sg-gateway-singbox.service`.

Отсутствующий неприменённый runtime не запускается искусственно. Ошибка одного сервиса не отменяет попытку обработать второй.

### 23. Дополнительная защита Xray

Усилены проверки текущего применённого состояния:

- отключённый профиль не выдаётся как рабочий;
- server-managed поля берутся с сервера;
- pending-кандидат не попадает в рабочую ссылку раньше Apply;
- проверяются Reality public key и short ID;
- обычная форма не должна случайно перезаписать серверную идентичность.

### 24. Фоновые операции

Доработаны:

- сохранение статуса после переподключения браузера;
- отдельный журнал шагов;
- обработка перезапуска панели;
- изоляция карточек операций;
- точные сообщения об ошибках;
- защита от ложного успешного завершения.

### 25. Обслуживание диска

Добавлены и уточнены:

- удаление старых SQLite-копий;
- предварительный расчёт количества и объёма;
- сохранение последних страховочных копий;
- отдельная очистка временных данных;
- журналирование результата;
- защита Full Backup и Safety Backup.

### 26. Системная диагностика

Исправлены:

- атрибуция памяти по службам;
- пороги предупреждений RAM;
- пороги свободного места;
- ложные критические статусы;
- отображение состояния конкретных runtime.

### 27. Интерфейс

Основные пользовательские изменения:

- три отдельные карточки AWG;
- унифицированная структура AWG 2.0, 3.0 и 3.1;
- скрытие неизменяемых UDP-портов из формы;
- общий DNS AWG;
- обновлённые статусы;
- унифицированные диалоги клиентов и устройств;
- переработанные QR и загрузка файлов;
- улучшенное сворачивание устройств;
- расширенный Maintenance и Restore;
- адаптация для низких разрешений;
- отдельные статусы Mieru, AnyTLS и TUIC.

### 28. Новая встроенная справка

Вместо шести коротких подсказок встроенная Help охватывает полный путь оператора:

- первый запуск;
- System;
- клиенты;
- подписки;
- Connections;
- три AWG-поколения;
- Xray;
- Mihomo/sing-box;
- Routing и WARP;
- Security;
- Backup/Restore;
- Update и установка;
- диагностика неисправностей.

## Что уже было в 022.04

Следующие возможности не следует рекламировать как полностью новые функции 022.06:

- Dual Stack IPv4 + IPv6;
- AWG 3.0 userspace;
- отдельные ULA-подсети AWG;
- семейная маршрутизация IPv4/IPv6;
- раздельный WARP IPv4 и IPv6;
- ручное создание WARP;
- базовая SG Subscription;
- подписки для отдельных устройств;
- Base64-совместимый транспорт подписки;
- Hysteria 2 Off / Salamander / Gecko;
- XHTTP/XMUX presets;
- базовый Full Backup;
- Safety Backup перед Update;
- атомарное обновление GeoIP и GeoSite;
- low-resolution layout;
- production WSGI.

В 022.06 эти компоненты сохранены, расширены или исправлены, но их происхождение относится к 022.04.

## Обновление с 022.04

На существующей поддерживаемой установке используйте стандартный Update:

```bash
curl -4 -fsSL https://raw.githubusercontent.com/s-gor/sg-gateway-v22/stable-02206/deploy/update-from-github.sh \
| sudo env SG_GATEWAY_GITHUB_BRANCH=stable-02206 bash
```

Перед обновлением рекомендуется скачать актуальный Full Backup и не закрывать SSH-сеанс до финального результата.
