# SG-Gateway 0.1.0-022.06 — полная справка

SG-Gateway — веб-панель для одного самостоятельного Ubuntu-сервера. Она устанавливает и обслуживает VPN-подключения, клиентов, устройства, подписки, маршрутизацию, резервные копии и системную диагностику.

Актуальный стабильный канал: `stable-02206`.

Поддерживаемая система: **Ubuntu 24.04**.

> Не публикуйте приватные ключи, пароли, UUID, subscription token и содержимое клиентских конфигураций. Если приватный ключ был опубликован, удалите соответствующий доступ и создайте новый.

## Установка, обновление и удаление

### Чистая установка

Clean Install предназначен только для нового сервера без установленного SG-Gateway.

```bash
curl -4 -fsSL https://raw.githubusercontent.com/s-gor/sg-gateway-v22/stable-02206/deploy/install-from-github.sh \
| sudo env SG_GATEWAY_GITHUB_BRANCH=stable-02206 bash
```

Установщик:

- проверяет Ubuntu 24.04;
- ожидает завершения `cloud-init`;
- проверяет свободное место;
- обновляет Ubuntu;
- устанавливает приложение и управляемые runtime;
- создаёт первоначальное состояние панели;
- проверяет запуск основных компонентов.

Если Ubuntu требует перезагрузку, установщик завершится с соответствующим сообщением. Выполните:

```bash
sudo reboot
```

После повторного входа запустите ту же команду Clean Install ещё раз.

Clean Install не используется для обновления существующей панели. При обнаружении установленного SG-Gateway он должен остановиться до изменения системы.

### Обновление существующей установки

```bash
curl -4 -fsSL https://raw.githubusercontent.com/s-gor/sg-gateway-v22/stable-02206/deploy/update-from-github.sh \
| sudo env SG_GATEWAY_GITHUB_BRANCH=stable-02206 bash
```

Update выполняет отдельную безопасную транзакцию:

- проверяет установленную систему;
- создаёт Safety Backup;
- загружает исходники в staging;
- проверяет source integrity;
- сохраняет базу, конфигурации, сертификаты, runtime и состояние служб;
- переключает код;
- проверяет Panel, HostD, HTTPS и VPN-службы;
- автоматически выполняет rollback при ошибке.

Не закрывайте SSH-сеанс до итогового сообщения updater.

### Полное удаление

```bash
curl -4 -fsSL https://raw.githubusercontent.com/s-gor/sg-gateway-v22/stable-02206/deploy/uninstall-from-github.sh \
| sudo env SG_GATEWAY_GITHUB_BRANCH=stable-02206 bash
```

Для подтверждения введите точно:

```text
DELETE SG-GATEWAY
```

Full Uninstall удаляет приложение, данные, резервные копии, управляемые конфигурации, SG-службы, интерфейсы и runtime. Общие пакеты Ubuntu остаются установленными.

После полного удаления можно выполнить Clean Install на том же сервере.

## Первый запуск

1. Откройте адрес панели, показанный установщиком.
2. Войдите под учётной записью администратора.
3. Откройте **System** и убедитесь, что панель и HostD работают.
4. Откройте **Connections** и проверьте публичный адрес, страну и состояние нужных протоколов.
5. При необходимости настройте HTTPS в **Security**.
6. Откройте **Clients**, создайте клиента или используйте первоначальный `sg-admin`.
7. Выберите протоколы для конкретного устройства.
8. Скачайте файл, скопируйте ссылку либо откройте QR-код.
9. Проверьте подключение с мобильной сети и Wi-Fi.
10. После завершения настройки создайте Full Backup в **Maintenance**.

Первоначальный `sg-admin` рассчитан на проверку установки. Для постоянного использования рекомендуется создавать отдельного клиента для каждого человека и отдельное устройство для каждого телефона, компьютера или роутера.

## Система и состояние служб

Раздел **System** показывает фактическое состояние сервера:

- версию панели;
- публичные IPv4 и IPv6;
- состояние Dual Stack;
- загрузку процессора;
- использование памяти;
- свободное место;
- состояние управляемых служб;
- предупреждения, требующие внимания.

Красный статус одной необязательной службы не всегда означает, что вся панель не работает. Сначала определите, какой именно протокол затронут.

Перед изменением подключений проверьте:

- доступность панели;
- свободное место;
- отсутствие незавершённой операции;
- состояние Nginx и HTTPS;
- состояние протокола, который будете изменять.

## AmneziaWG 2.0, 3.0 и 3.1

В SG-Gateway 022.06 три независимых поколения AmneziaWG.

| Профиль | Runtime | Интерфейс | UDP-порт | Назначение |
|---|---|---:|---:|---|
| AWG 2.0 | классический AmneziaWG | `awg0` | 585 | максимальная совместимость с клиентами AWG 2.x |
| AWG 3.0 | отдельный userspace runtime 3.0 | `awg3` | 586 | профиль поколения 3.0 |
| AWG 3.1 | отдельный userspace runtime 3.1 | `awg31` | 587 | профиль поколения 3.1 с расширенным protocol state |

Профили не заменяют друг друга. Для одного устройства можно выдать один, два или все три AWG-профиля.

### Общий DNS

DNS задаётся один раз для всех AWG-профилей. Изменение применяется к AWG 2.0, 3.0 и 3.1 и синхронизируется с существующими credentials без смены клиентских ключей.

Допускается от одного до четырёх IPv4- или IPv6-адресов DNS, разделённых запятыми.

### Создание AWG-клиента

1. Откройте клиента или устройство.
2. Выберите нужное поколение AWG.
3. Сохраните изменения.
4. Дождитесь статуса применённого профиля.
5. Скачайте отдельный `.conf` или откройте QR-код.
6. Импортируйте профиль в совместимый AmneziaWG-клиент.

AWG-конфигурация является файлом, а не обычной URL-ссылкой. Обычный WireGuard-клиент может не понимать параметры AmneziaWG.

### Когда AWG не подключается

Проверьте:

- профиль создан после последней переустановки сервера;
- клиент не был удалён в панели;
- используется правильный порт 585, 586 или 587;
- публичный endpoint актуален;
- соответствующая служба активна;
- UDP не блокируется провайдером или firewall;
- ключ сервера в файле соответствует текущей установке.

После полного удаления и чистой установки старые конфигурации обычно перестают работать, поскольку серверные ключи и peers создаются заново. Создайте новый доступ и импортируйте новый файл.

## Xray: Reality и XHTTP

SG-Gateway поддерживает несколько Xray-профилей, включая:

- VLESS Reality TCP;
- VLESS XHTTP Reality;
- VLESS XHTTP TLS;
- связанные режимы XMUX;
- Hysteria 2, когда он включён в текущей конфигурации.

Публичные ссылки строятся из текущего применённого серверного состояния. Неприменённый кандидат не должен попадать в рабочие клиентские ссылки.

Перед выдачей доступа проверьте:

- публичный host;
- порт профиля;
- SNI или server name;
- Reality public key;
- short ID;
- включён ли профиль;
- завершено ли применение изменений.

Для XHTTP клиентские параметры XMUX настраиваются отдельно от серверного inbound. Не вставляйте произвольный JSON без понимания параметров клиента.

## Mieru, AnyTLS и TUIC v5

В одном блоке Connections отображаются три независимых listener:

- **Mieru** обслуживается Mihomo;
- **AnyTLS** обслуживается sing-box;
- **TUIC v5** обслуживается sing-box.

Для AnyTLS и TUIC требуется рабочий HTTPS-домен. Пока сертификат не настроен, эти протоколы могут быть недоступны.

Кнопки **Сохранить**, **Проверить** и **Применить** относятся к настройкам. Перезапуск используется только для уже применённой конфигурации и не заменяет Apply.

Если один движок не запущен, это не должно автоматически блокировать другие протоколы панели. Проверяйте статусы Mieru, AnyTLS и TUIC отдельно.

## Клиенты, устройства и подписки

### Клиент и устройство

Клиент — человек или логический доступ. Устройство — конкретный телефон, компьютер, планшет или роутер.

Каждое устройство получает собственные:

- UUID и пароли;
- AWG-ключи;
- credentials;
- ссылки и файлы;
- QR-коды;
- subscription token.

Не используйте один профиль на большом числе устройств. Отдельные credentials упрощают отзыв доступа и диагностику.

### Выбор протоколов

Для клиента или устройства можно выбрать только нужные протоколы. Допустим AWG-only вариант без Xray и SG Client.

Если выбраны только AWG 2.0, 3.0 и 3.1, обычная SG Client subscription может не формироваться. В этом случае используйте отдельные AWG-файлы и QR-коды.

### SG Subscription

SG Subscription предназначена для совместимого клиентского приложения. Она может содержать несколько профилей одного устройства и обновляться без повторного ручного импорта каждой ссылки.

Основные правила:

- subscription token является секретом;
- каждое устройство имеет отдельную подписку;
- AWG 3.0 и AWG 3.1 представлены как разные профили;
- удалённый или отключённый доступ не должен выдаваться как активный;
- после смены credentials подписку следует обновить в клиенте.

### Router JSON Subscription

Для роутеров доступна отдельная Router JSON Subscription. Она предназначена для совместимых интеграций, включая варианты для OpenWrt/HomeProxy и Keenetic/XKeen.

Не путайте Router JSON Subscription с обычной SG Subscription: форматы и получатели различаются.

### QR-коды и файлы

Перед сканированием проверьте подпись над QR-кодом. QR может содержать:

- отдельный профиль;
- AWG-конфигурацию;
- SG Subscription;
- Router Subscription.

Если приложение не принимает QR, скачайте соответствующий файл или скопируйте ссылку вручную.

## Маршрутизация и WARP

Routing определяет, через какой выход пойдёт трафик.

Доступные семейные действия могут включать:

- SG-Gateway IPv4;
- SG-Gateway IPv6;
- WARP IPv4;
- WARP IPv6;
- Block.

Между IPv4 и IPv6 нет скрытого автоматического fallback. Правило должно соответствовать доступному семейству адресов.

WARP является необязательным outbound и настраивается отдельно. Ошибка WARP IPv6 не должна отключать WARP IPv4, и наоборот.

### GeoFiles

GeoIP и GeoSite обновляются парой:

1. выберите источник;
2. выполните проверку;
3. убедитесь, что категории пользовательских правил существуют;
4. примените обновление;
5. дождитесь проверки будущего Xray candidate.

Если новая пара не содержит категорию, используемую пользовательским правилом, обновление должно блокироваться до исправления правила.

## HTTPS и безопасность

HTTPS необходим для безопасной работы панели через интернет и для протоколов, использующих TLS.

Рекомендации:

- используйте уникальный надёжный пароль администратора;
- не публикуйте порт панели без необходимости;
- настройте DNS домена до выпуска сертификата;
- убедитесь, что домен указывает на текущий сервер;
- храните Full Backup как секрет;
- не пересылайте диагностику публично без проверки содержимого;
- после публикации приватного ключа отзовите доступ.

После восстановления на другом сервере проверьте домен, сертификат, Nginx и публичный endpoint всех протоколов.

## Резервные копии и восстановление

### Full Backup

Full Backup предназначен для переноса или аварийного восстановления всей установки. Он включает необходимые данные панели, клиентов, credentials, ключей, сертификатов и runtime-состояния.

Создавайте Full Backup:

- после первоначальной настройки;
- перед крупным изменением Routing;
- перед переносом на другой VPS;
- перед ручным обслуживанием системы;
- после добавления важных клиентов.

Скачанный `.sgbackup` храните в защищённом месте.

### Full Restore

Типовой перенос:

1. создайте Full Backup на старом сервере;
2. установите SG-Gateway на чистую Ubuntu 24.04 нового сервера;
3. откройте Maintenance;
4. загрузите `.sgbackup`;
5. дождитесь проверки архива и создания Safety Backup;
6. дождитесь пересборки runtime;
7. проверьте новый адрес панели и службы;
8. протестируйте клиентские подключения.

Restore проверяет архив до замены данных. При критической ошибке система должна вернуть Safety Backup.

### Clients & Keys и DATA Backup

Для отдельных задач доступны более узкие переносимые копии клиентов, ключей или данных. Они не заменяют Full Backup, когда требуется перенос сертификатов и полного состояния сервера.

### SQLite Restore

Загрузка отдельной SQLite-базы используется только при понимании состава файла. Перед применением база проверяется, а текущее состояние страхуется.

## Обслуживание и очистка

Maintenance содержит:

- Full Backup и Restore;
- DATA Backup;
- операции с SQLite;
- восстановление AWG runtime;
- журнал операций;
- диагностику;
- очистку старых локальных копий;
- сведения о фоновых задачах.

Удаление старых локальных SQLite-копий не должно удалять последние страховочные файлы, Full Backup или Safety Backup updater.

Не запускайте несколько опасных операций одновременно. Дождитесь завершения Update, Restore или runtime repair перед следующей операцией.

## Диагностика и типовые неисправности

### Панель не открывается

1. Проверьте, завершилась ли установка или операция Update.
2. Проверьте доступ к серверу по SSH.
3. Откройте System или Recovery, если локальный адрес доступен.
4. Проверьте Nginx, Panel и HostD через диагностику.
5. Проверьте свободное место.
6. Не переустанавливайте сервер до сохранения журналов и резервной копии.

### Профиль импортируется, но не подключается

Проверьте:

- профиль относится к текущей установке;
- endpoint и порт актуальны;
- клиент поддерживает конкретный протокол;
- служба активна;
- изменения применены;
- firewall пропускает нужный TCP или UDP порт;
- системное время клиента и сервера корректно;
- профиль не отключён и не удалён.

### Работает один протокол, но не другой

Это возможно: протоколы обслуживаются независимыми runtime. Проверяйте конкретную службу и конкретный порт, а не только общий статус панели.

### После переустановки старые профили не работают

Это ожидаемо, если не выполнялся корректный Restore. Новая установка создаёт новые серверные ключи и peers. Создайте клиентов заново либо восстановите проверенный Full Backup.

### AnyTLS или TUIC недоступны

Проверьте HTTPS, домен, сертификат и состояние `sg-gateway-singbox.service`.

### AWG 3.0 или 3.1 требует восстановления

Откройте Maintenance и используйте соответствующее восстановление runtime. Оно должно сохранить существующие credentials и настройки, если их состояние целостно.

### Что приложить к сообщению об ошибке

- версию SG-Gateway;
- Ubuntu version;
- название протокола;
- точный этап, на котором возникла ошибка;
- статус соответствующей службы;
- обезличенный фрагмент журнала;
- указание, была ли чистая установка, Update или Restore.

Не публикуйте приватные ключи, пароли, токены подписок и полный backup.

## Переход с 022.04

Для поддерживаемой установки 022.04 используйте обычный Update до `stable-02206`.

Главные изменения 022.06:

- добавлен независимый AWG 3.1;
- три AWG-профиля работают одновременно;
- расширены клиенты, устройства, QR и подписки;
- добавлены Router JSON Subscription;
- усилены Full Backup/Restore и перенос Clients & Keys;
- усилен exact-commit updater и rollback;
- опубликован официальный Full Uninstall;
- проверен сценарий удаления и повторной установки;
- расширены Maintenance, диагностика и встроенная справка.

Dual Stack, AWG 3.0, семейная маршрутизация, базовая SG Subscription, WARP по семействам, Hysteria 2 Gecko и XHTTP/XMUX уже существовали в 022.04 и в 022.06 были сохранены или доработаны.

Полный перечень отличий: [CHANGES-02204-TO-02206.md](CHANGES-02204-TO-02206.md).
