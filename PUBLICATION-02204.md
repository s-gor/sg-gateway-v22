# SG-Gateway 0.1.0-022.04 Fix30 — кандидат на выпуск

Статус: **DEV / prerelease**. Ветка: `fix30-ipv6-dual-stack`.

Версия опубликована для финальной установки и проверки на реальном сервере. После подтверждения clean install, обновления существующей установки и клиентских подключений prerelease можно переводить в стабильный выпуск.

## Версия и проверка обновления

- Исходная стабильная версия: `0.1.0-021.12` (`main`).
- Целевая версия: `0.1.0-022.04 Fix30` (`fix30-ipv6-dual-stack`).
- После Update панель и файл `/opt/sg-gateway/VERSION` должны показывать `0.1.0-022.04`.

### 1. Установка стабильной 0.1.0-021.12

На чистой Ubuntu:

```bash
curl -fsSL https://raw.githubusercontent.com/s-gor/sg-gateway-v22/main/deploy/install-from-github.sh | sudo bash
```

### 2. Update до 0.1.0-022.04 Fix30

На сервере с уже установленной `0.1.0-021.12`:

```bash
curl -fsSL https://raw.githubusercontent.com/s-gor/sg-gateway-v22/fix30-ipv6-dual-stack/deploy/update-from-github.sh | sudo env SG_GATEWAY_GITHUB_BRANCH=fix30-ipv6-dual-stack bash
```

### 3. Проверка версии

```bash
sudo cat /opt/sg-gateway/VERSION
```

Ожидаемый результат:

```text
0.1.0-022.04
```

## Главное в версии

Fix30 объединяет полноценный **Dual Stack IPv4 + IPv6**, изолированный **AWG3 userspace**, раздельную проверку семейств WARP, явную **семейную маршрутизацию**, безопасное обновление без разрушения рабочего runtime, расширенный SG Subscription и накопленные исправления интерфейса.

IPv4 остаётся обязательной совместимой основой. Отсутствие публичного IPv6 считается нормальным и не должно прерывать установку. Работа VPS только с IPv6 в эту версию не входит.

## Dual Stack IPv4 + IPv6

- Добавлены отдельные runtime-значения публичных IPv4 и IPv6 с сохранением старого параметра публичного адреса для обратной совместимости.
- Публичный IPv6 определяется локально, без зависимости от внешнего HTTP-сервиса определения адреса.
- IPv6-адреса в URI оформляются безопасно, в квадратных скобках.
- Xray использует dual-stack listener при наличии публичного IPv6; локальная панель при этом остаётся локальной.
- На странице «Система» отдельно отображаются IPv4, IPv6 и состояние Dual Stack.
- Если IPv6 отсутствует, сохраняется штатный IPv4-only режим без ошибки установки.

### AWG2

- Существующая IPv4-адресация полностью сохранена.
- При Dual Stack создаётся отдельная детерминированная IPv6 ULA-подсеть `/64` для AWG2.
- Клиент получает IPv4 и IPv6, а серверный peer — существующий IPv4 host route и отдельный IPv6 `/128`.
- В клиентском профиле используются оба семейства адресов.

### AWG3 userspace

- AWG3 изолирован от AWG2 и работает через собственный userspace runtime 3.x.
- Параметры H1–H4 и генерация runtime не зависят от пространства AWG2.
- Для AWG3 используется отдельная IPv6 ULA-подсеть `/64`.
- Userspace helper корректно разбирает и применяет одновременно IPv4- и IPv6-адреса интерфейса.
- `sg-gateway-awg3` включён в список полноценных служб SG-Gateway.
- Полное удаление останавливает и удаляет службу, интерфейс, socket и runtime-состояние AWG3.

## WARP

- Clean install больше не регистрирует и не создаёт WARP автоматически. WARP создаётся вручную на странице Outbounds.
- Существующее состояние WARP сохраняется при обновлении.
- Используется одно WireGuard-ядро WARP; IPv4 и IPv6 работают как отдельные семейные шлюзы.
- Поддержка профилем и реальная доступность проверяются раздельно.
- IPv4 и IPv6 тестируются независимо через Cloudflare trace.
- Ошибка IPv6 отключает только WARP IPv6; ошибка IPv4 — только WARP IPv4.
- Скрытый fallback с WARP на прямой выход запрещён.

Проверка на реальном сервере уже подтверждала `warp=on` отдельно для IPv4 и IPv6.

## Семейная маршрутизация (Family Routing)

Для правил доступны пять явных действий:

1. `SG-Gateway · IPv4`
2. `SG-Gateway · IPv6`
3. `WARP · IPv4`
4. `WARP · IPv6`
5. `Заблокировать`

- Между IPv4 и IPv6 нет автоматического fallback.
- Прямые IPv4/IPv6-выходы используют явную стратегию семейства Xray.
- WARP IPv4/IPv6 используют семейные шлюзы перед общим WARP core.
- Старые действия `direct` и `warp` безопасно мигрируют в IPv4-варианты.
- Итоговое правило для остального трафика также является семейно-явным.
- Исправлено отсутствие действия «Заблокировать» для остального трафика.
- Исправлена ошибка backend, которая заменяла `default_action=block` на `direct4`.
- Для LAN доступны только SG-Gateway IPv4, SG-Gateway IPv6 или Block.

## Безопасное обновление (Non-destructive updater)

- Обновление сохраняет виртуальное окружение, assets, AWG3 runtime, сертификаты и текущее HTTPS-состояние.
- Safety Backup сохраняет состояние служб и runtime, необходимое для полноценного rollback.
- Перед остановкой panel/HostD проверяется свободное место для Safety Backup.
- Незавершённые каталоги backup автоматически удаляются после неудачной упаковки.
- Количество успешно сохранённых Safety Backup ограничено, чтобы они не заполняли диск.
- Из архива исключено повторное добавление путей, уже покрытых родительским каталогом.
- Удалена массовая смена владельца всего каталога приложения.
- После обновления проверяются Clients, HTTPS/TLS, AWG3 и все ранее активные службы.
- Защищённый runtime env проверяется через приватную временную копию без ослабления прав.
- При любой ошибке автоматически восстанавливается состояние до обновления.

Технические маркеры регрессионного контракта: `checks required disk space before stopping panel/HostD`; `bounded history (two by default)`.

## SG Subscription и клиенты

Техническое название контракта в тестах совместимости: `SG subscription`.

- Добавлены схема, хранилище и HTTP-совместимость SG Subscription.
- Подписка и QR создаются отдельно для каждого устройства.
- Поддерживаются Base64 body и совместимый текстовый формат.
- Состояние доступа и credentials хранятся независимо для каждого устройства.
- В интерфейсе клиента доступны обе генерации AWG.
- Старые credentials сохраняются при миграции и rollback.
- Представление клиентов и устройств упрощено без потери технических экспортов.

## Hysteria 2: Off / Salamander / Gecko (Hysteria2 Gecko)

- Добавлены явные режимы Off, Salamander и Gecko.
- Gecko использует проверенный Salamander FinalMask с управляемым `packetSize=512-1200`.
- Маркер управляемого состояния предотвращает ошибочное принятие активного слоя за пользовательский базовый FinalMask.
- Добавлена миграция первой реализации Gecko в линии 022.04.
- Из URI Hysteria 2 удалён искусственный `alpn=h3`; серверная настройка ALPN остаётся независимой.
- Сохранено закреплённое ядро Xray 26.6.27.
- Интерфейс Obfuscation упрощён, внутренний разделитель удалён; runtime-логика не менялась.

## XHTTP и XMUX

- Добавлены управляемые XMUX-пресеты и экспертный режим для клиентских XHTTP-экспортов.
- Standard соответствует принятому контракту SG-Panel.
- Добавлен уменьшенный preset с проверкой конфликтующих значений.
- XHTTP Reality для клиента нормализован в `stream-one`.
- Существующий клиентский `extra` сохраняется и дополняется управляемыми значениями XMUX.
- XMUX никогда не добавляется в серверный XHTTP inbound.
- XHTTP TLS сохраняет независимый выбор клиентского mode.
- Вместо пассивных строк используются видимые кнопки режимов; по нажатию открывается окно с точными значениями preset.

Технический маркер регрессионного контракта: `parameter dialog with the exact preset values before save`.
